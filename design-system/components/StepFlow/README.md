分步方向过渡：多步确认和向导在原位换内容时，前进让新内容从右侧进入，后退让它从左侧进入，让人知道自己是往前走还是往回退。

## 用法
- 结构：`.step-view` 里放每一步的 `.step-pane`，同一时间只有一步不带 `hidden`。每一步 `tabindex="-1"`，用 `aria-labelledby` 指向这一步的问题。用在 ApprovalCard 里时，头部的 `.approve-step` 写“2 / 3”。
- 进入：新的一步从 `enter-opacity`、横向位移 `enter-shift`（前进为正，后退为负）过渡到原位，一个 `dur`。原位替换只播放进入，不等旧的一步退出。
- 换步之后把焦点移到新的一步（`focus({ preventScroll: true })`），读屏会读出新的问题；这一步自身不画焦点环，它不是可操作的控件。
- 按钮：`.act.ghost`“上一步”（第一步禁用）+ 一个主操作（ApprovalCard 里是“采用所选方案”）。最后一步之后给出结果，并提供“重新开始”这类明确的后续操作。
- 减弱动效：直接换内容，焦点照样移动。

## 不要
- 不要整页横向滑动或翻页；只动这一块的内容。
- 不要让前进和后退用同一个方向。
- 不要在换步时清空用户已经做出的选择；后退要能看到之前选的项。
