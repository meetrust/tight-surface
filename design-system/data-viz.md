# 数据可视化

图表是这个系统的主角，所以单独规定。核心要求是：图表里的每一个字在任何宽度下都看得清，每一种颜色在整页里含义不变。

## 选型
- 网页里的图表一律原生实现，规则和常见图形的做法见“图表实现”。
- 下面凡是提到 Mermaid 的条目，只适用于 `docs/` 下的 Markdown 手册和写明了原因的例外；README 不用 Mermaid。这时版本要固定到具体号（如 `mermaid@11.16.1`），用 `theme: "base"` 加 `themeVariables` 读取本系统的 token，不另写颜色。
- 不用 3D 效果（数据本身是三维的除外，见“图表实现”）、不用双轴、不用多于 8 个系列的饼图。

## 颜色
- 系列色按 `l0`–`l7` 的固定顺序分配，同一个对象在所有图里颜色相同（例如 nanoGPT 在雷达、饼图、甘特图里都是 `l4`）。
- 必经关系用实线，可选或推荐用虚线；线型图例写在图脚（FigKey 的 `.keys`）。
- 热力格用 `heat-1`–`heat-5`，格内同时写数字，不靠颜色单独表达。

## 文字可读
- 渲染后的图表文字不小于 12px。原生实现时文字本来就在 HTML 里，自然满足；不要把一张 700px 宽的图缩放到 324px 显示。
- 例外情况下使用 Mermaid 的做法：初始化前先测量容器宽度（测量时暂时隐藏图表源码，防止长源码行撑宽网格），再按这个宽度设置图的几何尺寸（雷达半径、象限图宽高），让 SVG 以接近 1:1 的比例渲染。渲染完成后，把 viewBox 裁到实际内容的范围。
- 隐藏图表库自带的图例，改用 HTML 的 FigKey，名称和数值始终是 13px。
- 连线标签做成不透明的芯片（底色 `chart-label-bg`，描边取该连线的颜色，12.5px）；永远不要用半透明底的标签。

## 标签避让
- 散点和象限图的点标签：先尝试放在点上方，冲突时依次尝试右侧、左侧、下方（留 3px 间距），选第一个与其他点、标签和象限标题都不重叠的位置。
- 象限标题如果压到数据点，就在象限内部水平移开，不移动数据点。
- 依赖图的连线标签与节点之间零重叠，交付前用脚本检查。

## 数据一致性
- 图与图、图与表之间的数字必须一致：饼图总和 = 标题里的总量，甘特图周数 = 阶段表周数，条形榜合计 = 首屏统计，预算分项之和 = 合计。
- 同一事物在各图里用同一个名称（例如统一写“makemore 2–6 讲”，不要在别处写成“makemore 1-5”）。
- 图注里写数据口径；估算值在页脚统一说明。

## 空值与缺失
- 值为 0 时，不要画出 8px 高的假柱子；可以留空，或者写“0”。
- 缺少数据的对象保留位置，用虚线或灰色图标表示“暂无”，并配文字说明。
