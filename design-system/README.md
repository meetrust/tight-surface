暗夜与白昼两套主题、单一琥珀强调、信息优先的界面语言。用于 AI 应用、开发工具、学习与数据叙事页面：同一套 token 和组件，可以搭出完全不同的版式，但一眼就能认出是同一个系列。默认主题是暗夜（Night）；白昼（Day）是浅色主题，组件和尺寸完全相同，只换颜色，见“浅色主题（Day）”。

## 设计原则

前五条是 Tight Surface 原有的方向，这里把每一条落成可检验的规则；后六条是从已交付页面和仓库中总结出的新增原则。

### 1. 信息优先
- 每一个视觉元素都要编码信息：颜色表示层级或轨道，位置表示顺序，线型表示必经 / 可选。不做纯装饰的图表。
- 每个数字都有出处或推导：统计卡的合计等于明细之和，饼图各段之和等于标题里的总量，页脚写明数据核对日期（`YYYY-MM-DD`）。
- 先给结论，再给细节：首屏放关键数字（StatTile），章节按“总览 → 关系 → 对象 → 对比 → 路线 → 来源”展开。

### 2. 紧凑
- 间距只取 `sp-1`–`sp-9`（4px 基准），组件内部用 `sp-2`–`sp-4`，卡片与图表 `sp-5`，章节之间 `sp-8`。
- 例外：组件内部 12px 以下的细小间距——图标与文字之间、圆点之间、胶囊和芯片的左右内边距、图内标记之间的缝隙——可以取刻度以外的值（如 2、3、6、10px），用来在固定高度里把文字和图标摆正；组件与组件之间、卡片、图表和章节的间距仍只取 `sp-1`–`sp-9`。
- 同类元素同一尺寸：内容胶囊 26px（`h-pill`），图形内微型标签 20px（`h-tag`），资源链接按钮 48px（`h-btn`），操作按钮和筛选按钮 36px（`h-filter`），复制按钮 28px（`h-copy`）。
- 应用控件（表单、操作按钮、下拉、Tabs）默认 36px（`h-filter`），表格和工具栏内的紧凑控件 26px（`h-pill`），40px（`h-nav-link`）只给导航，48px（`h-btn`）只给资源链接按钮 `.btn`。不出现这几档之外的控件高度。
- 标签一律 `nowrap`，空间不够就加省略号截断，而不是折行把高度撑开。数字用 tabular-nums。

### 3. 平静
- 界面强调色只有 `amber`（当前、焦点、选中、表头、编号）和 `ice`（链接、可点击）。`l0`–`l7` 只用于数据，不表示界面状态。
- 默认不用投影，靠 `rule` / `rule-2` 描边分层；发光和着色投影只在悬停、当前项或里程碑上出现。
- 背景纹理的不透明度不超过 0.11；全站只有一条缓动曲线（`ease`），状态过渡和编排的每一段都用同一个时长（`dur`），其余动效参数见“动效”。

### 4. 具触感
- 可交互元素在悬停时给出位移反馈：卡片和按钮上浮 2px（`lift`），横向条目右移 3–6px，描边变为该元素的数据色或 `ice`。
- 悬停效果只写在 `@media (hover: hover) and (pointer: fine)` 里；触屏上不出现残留的悬停态。
- 触控目标：导航链接 40px（`h-nav-link`），资源链接按钮 48px；应用控件默认 36px、紧凑控件 26px，都不低于 WCAG 2.5.8 要求的 24px。
- 这条同样约束 JS：`pointerenter` / `pointerleave` 只响应 `pointerType === "mouse"`，键盘聚焦只在 `:focus-visible` 时高亮，点击或轻点前先清除高亮（见“交互状态”）。

### 5. 可访问性良好
- 文字对比度：`ink` / `dim` / `faint` 在 `void`、`panel`、`panel-2` 上全部 ≥4.5:1（`faint` 在 `panel-2` 上 4.7:1，是下限）；Day 主题同样满足，数值见“浅色主题（Day）”。
- 焦点环：`:focus-visible` 2px `amber` 实线、外偏移 3px，在所有底色上 Night ≥9.1:1、Day ≥5.1:1。
- `prefers-reduced-motion: reduce` 时关闭全部动画、过渡和平滑滚动；自动开始、持续超过 5 秒的动效有暂停按钮（WCAG 2.2.2），见“动效”。
- 图标装饰用 `aria-hidden`，含义由文字承担；只有图标的按钮必须有 `aria-label`；状态不靠颜色单独表达。
- 表单字段都有看得见的标签（`<label>`，或 Kumo 组件自带的 `label`）；占位符只写示例（“如 CS229”），不能代替标签，占位文字对比度同样 ≥4.5:1。
- 会横向滚动的表格、代码和图表容器要能用键盘滚动（`tabindex="0"` + `role="region"` + 全页唯一的 `aria-label`）；只靠图形表达数值的元素用 `role="img"` + `aria-label` 给出数值；`aria-label` 里原样包含可见文字。
- Windows 对比度主题（`forced-colors: active`）会把 background 换成页面底色：组件已给条形、图例色块和里程碑菱形设了 `forced-color-adjust: none`；页面自己用 background 画的数据标记同样处理，遮罩图标改用系统色 `CanvasText`（链接内用 `LinkText`）。

### 6. 同一系列，不同版式（新增）
- 必须相同的：全部 token、三套字体及分工、琥珀强调、胶囊和按钮尺寸、图标（Lucide）、焦点环、动效参数、FIG 编号格式、页脚的系列声明。
- 可以不同的：页面骨架（左侧目录 / 顶部导航）、首屏构图、背景纹理（40px 网格 / 24px 点阵）、章节标题样式（空心大编号 / 编号横条）、每页的标志性图形。
- 同一系列的页面在页脚互相署名，例如“与《斯坦福 AI 课程地图》同一设计系列”。

### 7. 可验证（新增）
- 规范必须能被脚本检查：文字规则、元素尺寸、截断、溢出、链接、数据一致性都有对应的检查项（见“交付验收清单”）。
- 页面级的十三项检查（占位内容、按钮文案、可见标签、主操作、并排对齐、行长、贴边、空白、章节间距，以及减弱动效、默认可读、可以暂停、动效参数四项动效检查）由仓库里的 `tools/page_check.py` 完成，组件预览由 `tools/check_components.py` 完成，两者的 FAIL 都为 0 才能交付。
- 交付前至少在 1440 / 1024 / 760 / 390 / 360 / 320 六个宽度下截图检查，并用 axe-core 扫描，零违规。
- 验收要覆盖交互状态，不只看静态截图：悬停、键盘、触屏轻点三种方式各走一遍。

### 8. 中文排版优先（新增）
- 中文与英文 / 数字之间加半角空格；中文语境使用全角标点；引号用“”；范围用 en dash（`8–12 h`）。
- 汉字与汉字之间、汉字与全角标点之间不加任何空格，包括全角空格（U+3000）；需要分隔并列项时用间隔号（·，两侧各留一个半角空格）或标点，不用空格凑间距。
- 标题用 `text-wrap: balance`；不留单字孤行，行首不能是“/”或标点（必要时用 `&nbsp;` 绑定）。
- 术语保留英文原名（Transformer、BPE、CUDA），首次出现给一句中文解释。

### 9. 原生实现优先（新增）
- 网页里的图表用原生 HTML / CSS 实现，内联 SVG 只画线条和形状；默认不引入 Mermaid、Chart.js、ECharts 等图表库，也不用依赖它们的组件（如 Kumo 的 6 个图表组件）。
- 需要阅读的文字一律放在 HTML 里，图不随 viewBox 整体缩放；窄屏时改变布局，而不是把图缩小。
- `docs/` 下的 Markdown 手册可以用 Mermaid，README 不用；网页里的例外（大型自动布局有向图）要写明原因。详细规则见“图表实现”。
- 数据本身是三维的（点云、空间轨迹、机械臂姿态）可以用 WebGL 画 3D（如 Three.js）：文字标签放在 HTML 里，不自动旋转，画面静止时停止渲染，并在旁边提供二维视图。只是为了看起来立体的 3D 图表（3D 柱状图、3D 饼图）不用。

### 10. README 原生可读（新增）
- 提交到 GitHub 的 README.md 只用 GitHub 能渲染的 Markdown 和白名单 HTML：不放截图、横幅、插画等内容图片，不用 Mermaid、数学公式和会被过滤的样式写法；唯一的图片是功能徽章和表格里的颜色标签。
- 浅色和深色主题、桌面和手机宽度下都能读；项目亮点用原生表格呈现，代替首屏大图。
- 中英双语对照，中文在前；数字、名称、链接取自页面数据，与页面一致；提交前跑检查脚本。详细规则见“GitHub README”。

### 11. 动效说明变化（新增）
- 动效只用来说明变化：入场、位置变化、数值变化、状态变化，以及表示“进行中”的循环；不做装饰性动效。
- 一次变化按“退出 → 移动 → 进入 → 连线”编排；留下的元素移到新位置，不瞬移；一组元素依次进入时，从焦点开始错峰。
- 默认可读：页面的初始状态就是最终状态，入场不从完全透明开始，数字不从 0 数起；持续超过 5 秒的动效有全页暂停按钮。
- 时长、缓动、位移和错峰都取 token，脚本里也一样。参数、八条规则、九个标准模式和不采用的动效见“动效”。

## 内容与文案

- 语气：陈述事实、判断明确，不用感叹号，不用营销词。第二人称用“你”。
- 标题：章节 h2 写名词短语（“学习路线与时间表”）；eyebrow 写对应的英文大写短语（“ROADMAP”）。
- 图表：图注左侧写“FIG.0n · 标题”，右侧写一句读图提示（“右上为硬骨头”“斜纹为选修 · 菱形为里程碑”）。
- 数字：带单位和口径，例如“≈200h · 标准路线 17 周”“$3 / GPU·小时”；估算值标注“经验估计”。
- 缺失状态要明说：“暂无公开链接”占位保留，而不是隐藏按钮。
- 按钮文案写明会发生什么：动词加对象（“导出 CSV”“删除模块”“采用所选方案”）。不用“了解更多”“查看更多”“详情”“点击这里”“确定”“确认”“提交”“是 / 否”这类通用文案；“取消”“关闭”“复制”“重试”这类含义明确的单个动词可以用。
- 上线前不留草稿痕迹：lorem ipsum、TODO、“待补充”“[公司名称]”这类占位文字，example.com 地址、555-01xx 或同一数字重复的电话，以及指向“#”的链接（页内操作用 `<button>`）。真正缺的内容按上一条写明“暂无”。
- 不用 emoji。

## 视觉基础

### 颜色
- 底色三层：页面 `void`，卡片 / 图表 / 表格 `panel`，表头 / 图注 / 二级面 `panel-2`。
- 文字四级：正文 `ink`，次级正文 `ink-2`，说明 `dim`，脚注与刻度 `faint`。`muted`（3.0:1）未达标，已不用于任何组件，“暂无”胶囊改用 `faint`；保留这个 token 只为兼容旧页面。对比度要按文字实际所在的底色算：琥珀淡底、着色节点这类变亮的底上，小字用 `dim`，不用 `faint`。
- 强调：`amber` 是唯一的界面强调色，琥珀实底上的文字用 `on-amber`；`ice` 只表示“可以点”。
- 数据色：`l0`（基础 / 中性）加 `l1`–`l7` 七个序列，按层级或轨道的顺序固定分配，整页不变。给元素设置 `style="--c: var(--lN)"`，由组件自行派生描边（45%）、淡底（12%）、渐变和发光。
- 正负反馈：`good` / `bad` 分别是 `l6` / `l5` 的别名，必须配合 `i-check` / `i-x` 图标、状态环或文字使用，不用 ✓ / ✕ 字符。
- 警告：`warn` 是 `l4` 的别名，规则同 `good` / `bad`。提示类状态（info）用中性的 `ink-2` 文字和 `ink` 6% 淡底，不用 `ice`：`ice` 只表示“可以点”。
- 浮层：下拉菜单、弹出列表、Toast 和输入框的底色用 `pop`（Night 为 `panel-2`，Day 为 `panel`），不加投影，靠 `rule-2` 描边分层；对话框遮罩为 `void` 80%。
- 热力：1–5 级用 `heat-N` 作底、`heat-N-ink` 作字，冷（蓝）→ 热（红），每级对比度 Night ≥7.2:1、Day ≥7.1:1。
- 唯一允许的渐变文字是主标题的强调词（`amber` → #ffd9a0）；Day 主题不用渐变，直接用 `amber`。
- 主题：Night 写在 `:root`，是默认值；在 `<html>` 上加 `data-theme="day"` 切换到浅色的 Day。颜色只通过 token 引用，组件里不写死 `#fff` 或深色 `rgba()`，这样换主题时不用改组件。

### 字体
- `display`（Chakra Petch）：编号、eyebrow、图注标签、表头、统计数字。
- `body`（Noto Sans SC）：全部中文正文与标题（标题用 900）。
- `mono`（JetBrains Mono）：仓库 / 课程代号、代码、关系胶囊、目录子项。
- 中文只用已加载的字重 400 / 500 / 700 / 900：正文、选项文字、胶囊 400，字段标签、操作按钮和筛选按钮 500，选中项 700，标题 900。`.btn` 写的 600 在中文里按 700 显示。
- 字号只取 `fs-2xs` 12、`fs-xs` 13、`fs-sm` 14、`fs-base` 15、`fs-body` 16、`fs-lg` 18、`fs-xl` 22，标题用 `fs-2xl` / `fs-hero` 两级流式字号。可见文字不小于 12px（导航编号和品牌标记 11px 除外）。
- 正文行高 1.8，卡片正文 1.75，标签 1.2。

### 间距与布局
- `sp-1`–`sp-9`：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96。组件内部 12px 以下的细小间距可以不在刻度上，见原则 2。
- 手册版式：左侧 `toc-w` 272px 目录 + 主栏，主栏左右内边距 clamp(20px, 5vw, 64px)；≤1024px 目录收进抽屉。
- 地图版式：`nav-h` 60px 吸顶导航 + 最大宽度 `wrap` 1160px 的内容区。
- 网格列一律写 `minmax(0, 1fr)`，子元素加 `min-width: 0`，防止长内容把页面撑出横向滚动。手机断点里改成单列时也写 `minmax(0, 1fr)`，不写 `1fr`：后者会被宽表的最小内容宽度撑宽，在 320px 下出现横向滚动。
- 全局写 `*, *::before, *::after { box-sizing: border-box; }`：规范里的尺寸（胶囊 26、主按钮 48、目录 272 等）都是含内边距和描边的外框尺寸。
- 断点：760px（`bp-mobile`）是两种版式共用的手机断点；表格和代码只在自身容器里横向滚动。
- 行长：段落和列表项每行不超过 75ch（16px 正文约 42 个汉字），主栏比这宽时给正文设 `max-width: 75ch`；标题、图注、标签、表格和代码不受此限。
- 手机宽度（≤760px）下，文字距屏幕左右边缘至少 16px（`sp-4`）；在自身容器里横向滚动的表格和代码不受此限。
- 并排的卡片、统计卡和图表卡顶边对齐：高度可以随内容不同，顶边必须在同一条线上。
- 不留大片空白：从左到右没有任何文字、图片、控件或数据标记的空白带，高度不超过 240px；同一页各章节标题上方的间距保持一致，与中位数相差不超过 25%。

### 圆角、描边与投影
- 圆角：`r-sm` 8（导航链接、规格条、操作按钮 `.act` 与 Kumo 控件）、`r-md` 12（资源链接按钮 `.btn`、统计卡、代码块）、`r-lg` 16（图表、模块卡、表格），胶囊用 `r-pill`。4–7px 只用在组件内部的小部件上，以及 28px 复制按钮和 26px 紧凑操作按钮（6px）。
- 描边：默认 1px `rule`；控件和悬停态用 `rule-2` 或数据色；虚线表示可选、暂缺或占位。
- 投影：只有 `shadow-drawer`（抽屉）和 `shadow-glow`（里程碑）是固定值；悬停投影用元素自身的数据色，例如 `0 14px 34px -20px var(--c)`。

### 背景
- 手册版式：`.ts-grid-bg`，40px 网格线（ice 4%）+ 右上琥珀、左侧冰蓝两团径向光。
- 地图版式：`.ts-dot-bg`，24px 点阵（ice 11%）+ 顶部琥珀、右侧粉色两团径向光。
- 同一页只用一种纹理。

### 动效
- 所有过渡写成 `transition: <属性> var(--dur) var(--ease)`，抽屉用 `dur-drawer`；不省略缓动，否则浏览器会用默认的 ease。
- 入场：`rise`（从 `enter-opacity` 上移 `enter-shift` 淡入），条形 `grow`（从 `grow-from` 横向展开，按 `--i` 错峰）；进行中：`pulse`（脉冲点）、`ring-spin`（状态环）和 `flow`（虚线流动），周期都是 `dur-loop`，后两者匀速，用 linear。
- `prefers-reduced-motion` 下全部关闭。完整规则、参数和标准模式见“动效”。

### 状态
- 悬停：位移 + 描边变色（只限精确指针）。
- 聚焦高亮：相关项保持 100%，无关项淡出；SVG `foreignObject` 里的 HTML 只改颜色，不用 opacity、transform、filter 或 transition（见“交互状态”）。
- 当前：`amber` 编号或文字 + 2–3px 琥珀线（导航底线 / 目录左竖条）。
- 选中：琥珀实底 + `on-amber`（筛选按钮、勾选框、单选、开关），筛选按钮同时设置 `aria-pressed`。
- 主操作：琥珀淡底，与 `.btn.video` 同款（`amber` 11% 底、55% 描边、`amber-ink` 文字）；不用琥珀实底的主按钮。危险操作同构，换成 `bad`。每组（按钮行、卡片、表单、对话框）只有一个主操作。
- 禁用 / 暂缺：虚线描边 + `faint` 文字 + `aria-disabled`，保持占位。
- 焦点：琥珀焦点环，不能被 `outline: none` 去掉。

## 图标

- 默认图标库是 Lucide，固定在 1.71.0：24×24 网格，描边 2，圆头圆角，`currentColor`。页面里不混用其他图标库；Kumo 组件内部的 Phosphor 图标是唯一例外。
- 静态页面和 Artifact 用内联 sprite：从 `icons/sprite.svg` 复制需要的 symbol，id 一律是 `i-` 加 Lucide 名（`i-arrow-up-right`），描边由 `.i` 提供，不从 CDN 加载。React 项目用 `lucide-react@1.71.0`，根节点包 `<LucideProvider className="i">`，组件名与 id 一一对应（`<ArrowUpRight />`）；连线图例的 `i-move-right`、`i-move-right-dashed` 经过裁剪或改造，React 里也用 sprite。细节和旧图标对照表见 Icon 组件。
- 尺寸按场景固定：胶囊和紧凑操作按钮 12px、外链箭头 / 图例 13px、资源链接按钮和操作按钮 15px、目录按钮 16px、回到顶部 18px、连线图例 22×14。
- 不用字符做图标（☰ ↑ ↗ ▶ ◆ ▍ ✓ ✕）；伪元素里需要图标时，用同一个 Lucide 图标的 path 作为 `mask`，并在 `forced-colors: active` 下改为 `forced-color-adjust: none; background: CanvasText`，否则图标会消失。例外只有两个：正文中表示流程的“→”，以及带 `aria-label` 的 ★ 星级。
- 本系统没有 Logo，品牌名用文字排出（上行 `brand-mark` 英文大写，下行中文名）。

## 组件选择

- 页面骨架：正文长、章节多时用 SideToc；单屏总览、章节不超过 7 个时用 TopNav。
- 章节开头：SectionHead（一个页面里只用一种写法）。
- 对象展示：深度介绍用 ModuleCard，总览网格用 ElementTile，纠正误区用 Callout。
- 数字：首屏用 StatTile，排名用 BarList，多维对比用 DataTable（可叠加热力格）。
- 图表外框一律用 Figure，图例用 FigKey；图表本身按“图表实现”一节原生实现。
- 链接与操作：Button（资源链接 `.btn` 48、操作 `.act` 36 / 26、筛选 `.fbtn` 36、复制 `.copy` 28）和 Chip。
- AI Agent 界面：思考过程用 ThinkingTrace，工具调用用 ToolCall，多步任务的进度用 TaskRow，需要用户拍板时用 ApprovalCard。
- 动效：筛选和排序后的网格用 Reflow，会更新的读数用 NumberRoll，任务和工具的状态用 StatusRing，单选切换用 SlideTabs，多步流程用 StepFlow，横向滚动的表格和代码用 ScrollFade；页面里有持续动效时放一个 PauseMotion。
- 应用控件（表单、浮层、导航、反馈）：用 Kumo 组件加适配层，取舍与写法见“Kumo 适配”。
